## 2. Anatomy of the Reported Result

While mathematically reproducible from the script, the score **0.99891 does NOT represent the true generalization score** on the competition task due to four critical architectural factors:

```text
┌─────────────────────────────────────────────────────────────────────────────────┐
│                           DECONSTRUCTING 0.99891                                │
├─────────────────────────────────────────────────────────────────────────────────┤
│ 1. Evaluated In-Sample: Evaluated on the exact training pairs used to fit trees.│
│ 2. Metric Mismatch: Pair-level binary F0.5 rather than Entity-level Macro F0.5. │
│ 3. Synthetic Benchmark Candidates: Evaluated on GT matches + synthetic negatives│
│    rather than noisy candidates from the blocking pipeline.                     │
│ 4. Singletons Omitted: True singletons with 0 candidate pairs were excluded.    │
└─────────────────────────────────────────────────────────────────────────────────┘
```

### Detailed Factor Breakdown (12-Point Forensic Audit):

| Audit Question | Audit Finding |
| :--- | :--- |
| **1. Which dataset was evaluated?** | `training_pair_features_v2.parquet` containing 43,125 pairs sampled from the first 5,000 Source-1 training entities. |
| **2. Which candidate population was used?** | Synthetic benchmark candidate set: 17,250 true positive pairs + 25,875 negative pairs generated by `train_model_v2.py`. NOT the blocking output. |
| **3. Was it pairwise or entity-level?** | **Pairwise binary classification**. Evaluated across flattened pairs ($y \in \{0, 1\}$) via `sklearn.metrics.precision_score` and `recall_score`. |
| **4. Which train/validation split was used?** | **None** for the reported 0.99891 (evaluated 100% in-sample on `X_all`, `y_all`). For the CV training, an ungrouped `StratifiedKFold(n_splits=5)` was used. |
| **5. Was GroupKFold used?** | **NO**. `StratifiedKFold` was used, resulting in 99.4% of validation Source-1 entities being present in the training fold (severe group leakage). |
| **6. How were negatives generated?** | 40% Soundex collisions, 30% first 4-character prefix collisions, and 30% in-country random distractors. |
| **7. Were hard negatives generated using validation labels?** | Ground truth labels from the full 5,000 S1 sample were used prior to splitting. In ungrouped CV, this leaked negative pairs across folds. |
| **8. Was the threshold tuned on the same validation data?** | Yes, the split thresholds ($S_2 = 0.65, S_3 = 0.50$) were selected on the same data. |
| **9. Were singleton S1 entities included?** | **Partially/Omitted**. Only 203 singletons that received synthetic negative pairs were in the table. 70 singletons with zero candidate pairs were completely dropped. |
| **10. Were multi-match entities evaluated correctly?** | **NO**. Multi-match entities contributed multiple pairs to the pooled binary metric rather than computing per-entity precision/recall and averaging. |
| **11. Was the final integrated candidate set used?** | **NO**. `candidate_pairs.tsv` was an empty stub (97 bytes). Model evaluated on synthetic pairs. |
| **12. Was the score obtained from OOF predictions or training predictions?** | **Training predictions (in-sample)** for 0.99891. For 0.99652, it was obtained from GroupKFold OOF predictions. |
